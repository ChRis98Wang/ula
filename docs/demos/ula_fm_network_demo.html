Training Diagnosis v0.4

为什么 loss 下降但预览视频仍然跳变

上一轮 50k step 的 loss 从约 2.0 降到 0.067，但最后预览仍有明显跳变。原因不是 parquet 清洗失败， 而是训练预览和模型结构本身还缺少长程、时间位置和速度约束。

4.0s 旧训练预览由 120 frames / 30Hz 固定产生
4.02 旧最终预览最大单帧跳变 rad/frame
120.6 旧最终预览最大速度 rad/s
0.20 clean_v1 数据清洗后最大单帧跳变上限
24s 新训练预览默认长程录像时长
3.0 新预览 processed 轨迹默认限速 rad/s
诊断点 证据
预览固定 4 秒 旧命令使用 --preview-frames 120，30Hz 下只能录出 4 秒，无法观察长程紧张到缓和。
生成采样无速度约束 旧预览在 joint_lShoulderPitch 出现 4.02 rad 单帧跳变；clean_v1 parquet 本身没有这种跳变。
Transformer 缺少帧位置编码 同一输入的不同帧会得到相同输出，模型不知道第 1 帧和第 100 帧的顺序，loss 下降也可能学不到连续动作。
语义分布偏弱 训练集中 neutral / unknown / null gesture 占多数，loss 下降不能直接证明模型学会了“紧张解释、逐渐平复”。
v0.4 改动 训练与预览影响
Sinusoidal frame embedding Action Expert 在每一帧看到不同时间位置；旧权重需要重新训练，不能只看旧 checkpoint。
训练预览默认 long mode 每次 preview 生成多段 long_motion，总时长默认 24 秒，不再只看 4 秒窗口。
预览后处理 保存 raw_trajectory 和 processed trajectory；processed 经过 velocity limit + smoothing，再录制 V2 MuJoCo。
质量统计写入 summary summary.json 记录 raw/processed 的 max_delta、mean_delta、max_velocity、mean_velocity。

Original Meta Paper

Meta Seamless Interaction 原始网络和训练方式

原论文训练的是 dyadic audiovisual motion model：输入双人语音 token，可选加入对方视觉行为， 输出 avatar 的 face latent 和 SMPL-H upper-body motion。这里先按论文原始版本说明，再和机器人版 ULA-FM 对比。

原始 Dyadic Motion Model 网络

Speech / Visual → Avatar Motion
Dyadic Audio 两个人的语音流，经 speech tokenizer 转成离散 speech tokens。
User Visual Optional 对方脸部 Imitator latent 或 body SMPL-H pose，作为视觉条件。
Condition Projection speech / visual 条件重采样到 motion 帧率，并投影到模型维度。
DiT Backbone Diffusion Transformer，RMSNorm + KQ-Norm self-attention。
Flow Matching 学习从噪声分布流向真实 motion latent 的速度场。
Face Motion expression code、head rotation、head/body translation。
Body Motion SMPL-H 上半身/手部关节旋转，使用 6D rotation 表示。

原始动作表示

Face + Body
face feature Imitator representation：expression code、head rotation、translation，拼成每帧 face latent。
body feature SMPL-H joint rotations，使用 6D rotation；论文主要保留上半身，忽略腿部关节。
joint model 把 face feature 和 body feature 拼接成 joint face+body motion feature，一起生成。
cascaded model Face2Body 或 Body2Face：先生成一侧，再用它条件化另一侧，减少头部/身体不对齐。

原始条件接入

Conditioning
audio condition 两路 speech token 共享 embedding table，拼接后编码为 dyadic speech condition。
rate alignment speech token rate 和 video/motion rate 不同，论文把 speech condition 重采样到 motion 序列长度。
fusion method 把 motion projection 和 condition projection 加到同一特征空间；论文发现这比 cross-attention 更对齐。
visual condition audiovisual 版本额外拼入 interlocutor visual features，让 avatar 对对方表情/姿态反应。

原始 Flow Matching 训练目标

Velocity Field
1

真实动作样本

从数据集中取真实 motion feature x，例如 face latent、SMPL-H body pose 或二者拼接。

x ∈ R^[T×D_motion]
2

采样噪声和流时间

采样高斯噪声 ε 和 t∈[0,1]，用线性路径构造 noisy latent。

x_t = t x + (1 - (1 - σ_min)t) ε
3

速度场监督

模型预测 vθ(x_t,t,c)，目标是从当前 noisy latent 指向真实数据分布的速度。

v_target = x - (1 - σ_min) ε
4

条件式回归

用 MSE 训练条件速度场；推理时从噪声开始解 ODE 生成动作。

L = E ||vθ(x_t,t,c) - v_target||²

原始可控生成：Emotion、Expressivity、Semantic Gesture

Codebook Control
Arousal / Valence A/V 连续值或 bucket token；支持固定情绪或动态情绪序列。
Expressivity Signals head rotation、eyebrow、mouth、gaze dynamism，bucketize 后控制表达强度。
Semantic Gesture 语义手势条件 G 或 VQ-VAE gesture code，解决 speech-only 很难学到长尾手势的问题。
Temporal Dropout 训练时随机把部分 gesture condition 替换成 null，让模型学会缺失条件下平滑过渡。
LLM Adapter 冻结 speech LLM；用 MLP Adapter 从 hidden states 预测 arousal、valence、gesture code。
Code-conditioned Motion motion model 同时吃 speech tokens 和 codebook conditions，生成更可控的 face/body motion。

Meta 原论文 vs 机器人版 Codebook ULA-FM

Mapping
模块 Meta 原论文 本项目机器人版
输入语义 双人 speech tokens，必要时加对方 visual features。 language_action_index 的 transcript、scenario、action、intent、mood、derived codes。
动作表示 face Imitator latent + SMPL-H 6D body rotations。 V2 机器人 15 维上肢关节角窗口 [120,15]。
主干模型 Diffusion Transformer / Flow Matching velocity field。 保留 Flow Matching Action Expert，输出机器人 joint trajectory velocity field。
情绪控制 Arousal / valence 连续值或 bucket condition。 arousal_bucket / valence_bucket + 连续 A/V 数值，作为机器人动作幅度、节奏和开放度条件。

安全层 面向 avatar 渲染质量和人评协议。 必须加 joint limit、velocity、acceleration、collision、CSV/ROS2 安全导出。
Network Architecture

Conditional Flow Matching Action Expert

左侧先把语言映射成可控 codebook，再和机器人状态融合；中间是动作流模型，右侧输出一个 V2 上肢轨迹窗口。 文本编码器第一版冻结，只训练 code adapter、条件融合层和动作专家。

Code 第一版来源与用途
intent_code 从 labels.intent、intent_text 和 transcript 派生；控制 greeting、refusing、explaining、waiting 等动作族。
gesture_code 从 action_description、关键词和人工规则派生；控制 wave、stop、point、open_hand_explain、crossed_arms、null。
arousal_code 把 arousal 连续值 bucketize 到 12 桶；控制速度、幅度、动作能量。
valence_code 把 valence 连续值 bucketize 到 12 桶；控制开放/收敛、友好/回避的表达倾向。
style_code 从 motion_style 与 motion_energy 派生；控制 relaxed、restrained、energetic、sharp、slow_safe。
当前缺口 需要补充的信息
语义手势 JSONL 目前没有显式 gesture_code；需要规则标注或人工审核 stop/wave/point/explain/null。
情绪类别 partial 里 observed_affect 都是 low_confidence_unknown；需要更可靠的 observed_affect 或只用 A/V bucket。
意图细分 当前 intent 主要是 explaining/waiting；需要从 transcript、prompt、3P-V/R 中提取 refusing、greeting、warning 等。
交互角色 需要 speaking/listening、turn-taking、是否回应对方动作；否则难学开放、收拢、停顿、轮替提示等上肢交互趋势。
目标方向 需要 target_direction 或目标对象侧向；否则 point/turn/open hand 只能学平均方向。
质量权重 需要把 flagged_frame_count、yaw_under_response、elbow_overfold 转成训练 sample_weight 或过滤规则。
Long Emotion v0.3

新训练和模型改动：让动作自己决定持续、转场和结束

v0.3 不再把生成动作理解成固定 4 秒。当前数据仍是 120 帧训练窗口，但模型已经加入 duration 和 transition 规划头；推理时由 planner 循环调用 Flow Expert，拼成长程情绪表达。

新增模块总图

Planner + Segment Flow + Original V2 Playback
语言/情绪条件 prompt、intent、gesture、A/V、style、q0
Condition Encoder 复用 v0.2 的 text/code/numeric/robot condition
Planner Head duration_sec + transition_logits[4]
Segment Flow Expert 按 planner 的时长生成 q[segment_T,15]
Continuity State 上一段末尾 q 作为下一段起点，减少段间跳变
Original V2 MuJoCo 加载 mujoco_robot_v2_meshdir.urdf，不再使用简化机器人
长程输出 plan.json + long_motion.csv + long_motion_original_v2.mp4
新增训练头 当前实现
duration_head softplus(MLP(cond)) + 0.25，输出每段动作预测持续秒数。
transition_head 4 类 logits：continue、emotion_change、action_change、end。
planner_loss smooth_l1(log1p(duration)) + 0.25 * cross_entropy(transition)。
flow_loss 仍然是 Conditional Flow Matching：MSE(vθ(x_t,t,c), x_data-z)。
总 loss L = L_flow + 0.05 * L_planner，先保证动作分布，再逐步增强时长和转场监督。
训练数据现实 解释
当前 parquet 51,101 episodes，每条仍是 120 帧固定窗口；这是现有数据事实，不等于最终长程数据。
当前 duration 监督 弱监督来自 episode length / fps，所以旧数据只能给 planner 一个可训练接口，不能充分学真实“解释多久”。
下一版数据 需要从整段 retarget CSV、transcript、A/V token 和 motion_energy 自动切出 variable-length 情绪段。
旧 checkpoint 已支持 strict=False 加载；旧权重能跑长程推理，但 planner head 是新初始化，必须重新训练才有质量。

长程推理循环

Loop Until End or Max Duration 
for segment_i in range(max_segments):
    cond_i = condition(prompt, q_last, previous_transition)
    duration_i, transition_i = planner_head(cond_i)
    q_i = flow_expert.sample(cond_i, frames=duration_i * fps)
    q_i[0] = q_last
    append(q_i)
    if transition_i == "end" and min_segments_satisfied:
        break

render original V2 MuJoCo:
  long_motion.csv -> long_motion_original_v2.mp4

Language Head Detail

语言头如何接入 Action Expert

第一版不要训练完整语言模型。我们冻结文本编码器，只训练 code adapter、language adapter、condition fusion、 FiLM/调制层和 action expert。这样数据量不大时更稳，也不会把语言模型训坏。

阶段 训练语言头吗 训练参数 理由
v0.1 不训练完整语言模型 Code Adapter、Language Adapter、code/numeric/state encoder、condition fusion、FiLM/AdaLN、action expert 样本量还小，冻结文本编码器能保持语义稳定；用中间 code 提高动作可控性和可调试性。
v0.2 可选 LoRA 只在 text encoder 最后 2-4 层加低秩 LoRA，rank 4 或 8 当动作描述和人工复核标签足够多时，让语言空间更贴近机器人动作域。
v1.0 多任务训练 增加 action caption head、style classifier head、gesture critic、trajectory critic 让模型同时学“描述动作”和“生成动作”，提升文本-动作对齐质量。
Training Graph

训练时同时学习动作速度场、时长和转场

v0.3 的主目标仍是条件速度场，但额外训练 planner head： 预测每段动作持续时间，以及 continue、emotion_change、action_change、end 四类转场。

训练流程图

Flow Matching Objective
1

读取训练窗口

从 LeRobot parquet 读取文本、语义、质量字段和 V2 关节序列；当前数据仍是固定窗口。

x_data ∈ R^[120×15]，future: x_data ∈ R^[T×15]
2

派生监督 code

从 labels、A/V 数值、transcript 关键词和动作描述派生 intent、gesture、style、A/V bucket。

c_code = {intent, gesture, a_bin, v_bin, style}
3

采样噪声和时间

采样高斯噪声 z 和连续流时间 t，构造中间状态 x_t。

x_t = (1 - t) · z + t · x_data
4

预测速度场

模型根据 x_t、t、text_emb、codebook condition 预测当前点应该流向真实动作的方向。

v_target = x_data - z
5

优化与验证

联合 flow 和 planner loss；定期生成长程 MuJoCo 预览，检查情绪表达是否持续且有转场。

L = L_flow + 0.05 · L_planner

推荐推理策略 先预测可解释的中间 code 和 planner 结果，再生成多个动作段；每段之间把上一段末尾 q 写回下一段起点。 这样可以形成 20-60 秒长程情绪表达，同时保留安全过滤和人工预览。
安全边界 低置信度 code、超限候选、碰撞候选、穿模候选全部降级为 null gesture + neutral style 或缩短当前 segment。 模型输出不是最终控制命令，必须被安全层接管。

Implementation Plan

最小可训练闭环

先做能 overfit、能采样、能预览的小模型。不要一开始做巨大网络，先证明语言条件和动作分布是可学的。

1. Dataset JSONL + CSV window loader，按 fps 读取源窗口，轨迹归一化，质量过滤，派生 codebook 监督。
2. Model Frozen text encoder + code adapter + condition fusion + planner head + Transformer flow expert。
3. Train 先用 partial overfit，再全量训练；记录 flow/code loss、preview 和 checkpoint。
4. Sample prompt 先生成可解释 code、duration、transition，再循环生成多段长程轨迹。
5. Validate 用原 V2 MuJoCo 录制 long_motion_original_v2.mp4，人工筛选高质量长程样本。
