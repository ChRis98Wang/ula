Original Meta Paper

Meta Seamless Interaction 原始网络和训练方式

原论文训练的是 dyadic audiovisual motion model：输入双人语音 token，可选加入对方视觉行为， 输出 avatar 的 face latent 和 SMPL-H upper-body motion。这里先按论文原始版本说明，再和机器人版 ULA-FM 对比。

原始 Dyadic Motion Model 网络

Speech / Visual → Avatar Motion
Dyadic Audio 两个人的语音流，经 speech tokenizer 转成离散 speech tokens。
User Visual Optional 对方脸部 Imitator latent 或 body SMPL-H pose，作为视觉条件。
Condition Projection speech / visual 条件重采样到 motion 帧率，并投影到模型维度。
DiT Backbone Diffusion Transformer，RMSNorm + KQ-Norm self-attention。
Flow Matching 学习从噪声分布流向真实 motion latent 的速度场。
Face Motion expression code、head rotation、head/body translation。
Body Motion SMPL-H 上半身/手部关节旋转，使用 6D rotation 表示。

原始动作表示

Face + Body
face feature Imitator representation：expression code、head rotation、translation，拼成每帧 face latent。
body feature SMPL-H joint rotations，使用 6D rotation；论文主要保留上半身，忽略腿部关节。
joint model 把 face feature 和 body feature 拼接成 joint face+body motion feature，一起生成。
cascaded model Face2Body 或 Body2Face：先生成一侧，再用它条件化另一侧，减少头部/身体不对齐。

原始条件接入

Conditioning
audio condition 两路 speech token 共享 embedding table，拼接后编码为 dyadic speech condition。
rate alignment speech token rate 和 video/motion rate 不同，论文把 speech condition 重采样到 motion 序列长度。
fusion method 把 motion projection 和 condition projection 加到同一特征空间；论文发现这比 cross-attention 更对齐。
visual condition audiovisual 版本额外拼入 interlocutor visual features，让 avatar 对对方表情/姿态反应。

原始 Flow Matching 训练目标

Velocity Field
1

真实动作样本

从数据集中取真实 motion feature x，例如 face latent、SMPL-H body pose 或二者拼接。

x ∈ R^[T×D_motion]
2

采样噪声和流时间

采样高斯噪声 ε 和 t∈[0,1]，用线性路径构造 noisy latent。

x_t = t x + (1 - (1 - σ_min)t) ε
3

速度场监督

模型预测 vθ(x_t,t,c)，目标是从当前 noisy latent 指向真实数据分布的速度。

v_target = x - (1 - σ_min) ε
4

条件式回归

用 MSE 训练条件速度场；推理时从噪声开始解 ODE 生成动作。

L = E ||vθ(x_t,t,c) - v_target||²

原始可控生成：Emotion、Expressivity、Semantic Gesture

Codebook Control
Arousal / Valence A/V 连续值或 bucket token；支持固定情绪或动态情绪序列。
Expressivity Signals head rotation、eyebrow、mouth、gaze dynamism，bucketize 后控制表达强度。
Semantic Gesture 语义手势条件 G 或 VQ-VAE gesture code，解决 speech-only 很难学到长尾手势的问题。
Temporal Dropout 训练时随机把部分 gesture condition 替换成 null，让模型学会缺失条件下平滑过渡。
LLM Adapter 冻结 speech LLM；用 MLP Adapter 从 hidden states 预测 arousal、valence、gesture code。
Code-conditioned Motion motion model 同时吃 speech tokens 和 codebook conditions，生成更可控的 face/body motion。

Meta 原论文 vs 机器人版 Codebook ULA-FM

Mapping
模块 Meta 原论文 本项目机器人版
输入语义 双人 speech tokens，必要时加对方 visual features。 language_action_index 的 transcript、scenario、action、intent、mood、derived codes。
动作表示 face Imitator latent + SMPL-H 6D body rotations。 V2 机器人 15 维上肢关节角窗口 [120,15]。
主干模型 Diffusion Transformer / Flow Matching velocity field。 保留 Flow Matching Action Expert，输出机器人 joint trajectory velocity field。
情绪控制 Arousal / valence 连续值或 bucket condition。 arousal_bucket / valence_bucket + 连续 A/V 数值，作为机器人动作幅度、节奏和开放度条件。
语义手势 gesture vocabulary 或 VQ-VAE code；训练时 temporal gesture dropout。 semantic_gesture / gesture_code：null、upper_body_gesture、pointing、crossed_arms、shrugging 等，后续扩 stop/wave。
LLM 作用 冻结 speech LLM，Adapter 预测 emotion/gesture code，不直接输出动作。 冻结 text encoder 或 LLM，Code Adapter 预测 intent/gesture/A-V/style code，不直接输出关节角。
安全层 面向 avatar 渲染质量和人评协议。 必须加 joint limit、velocity、acceleration、collision、CSV/ROS2 安全导出。

Code 第一版来源与用途
intent_code 从 labels.intent、intent_text 和 transcript 派生；控制 greeting、refusing、explaining、waiting 等动作族。
gesture_code 从 action_description、关键词和人工规则派生；控制 wave、stop、point、open_hand_explain、crossed_arms、null。
arousal_code 把 arousal 连续值 bucketize 到 12 桶；控制速度、幅度、动作能量。
valence_code 把 valence 连续值 bucketize 到 12 桶；控制开放/收敛、友好/回避的表达倾向。
style_code 从 motion_style 与 motion_energy 派生；控制 relaxed、restrained、energetic、sharp、slow_safe。
当前缺口 需要补充的信息
语义手势 JSONL 目前没有显式 gesture_code；需要规则标注或人工审核 stop/wave/point/explain/null。
情绪类别 partial 里 observed_affect 都是 low_confidence_unknown；需要更可靠的 observed_affect 或只用 A/V bucket。
意图细分 当前 intent 主要是 explaining/waiting；需要从 transcript、prompt、3P-V/R 中提取 refusing、greeting、warning 等。
交互角色 需要 speaking/listening、turn-taking、是否回应对方动作；否则难学开放、收拢、停顿、轮替提示等上肢交互趋势。
目标方向 需要 target_direction 或目标对象侧向；否则 point/turn/open hand 只能学平均方向。
质量权重 需要把 flagged_frame_count、yaw_under_response、elbow_overfold 转成训练 sample_weight 或过滤规则。

语言头如何接入 Action Expert

第一版不要训练完整语言模型。我们冻结文本编码器，只训练 code adapter、language adapter、condition fusion、 FiLM/调制层和 action expert。这样数据量不大时更稳，也不会把语言模型训坏。

Training Graph

训练时学习“从噪声流向真实动作”

训练目标不是预测下一个点，而是学习一个条件速度场。语言先被监督成中间控制码，再由 codebook 和机器人状态决定动作的意图、情绪表现、节奏和幅度。

训练流程图

Flow Matching Objective
1

读取训练窗口

从 JSONL 读取文本、标签和质量字段，从 CSV 读取对应时间窗口，得到真实动作 x_data。

x_data ∈ R^[120×15]
2

派生监督 code

从 labels、A/V 数值、transcript 关键词和动作描述派生 intent、gesture、style、A/V bucket。

c_code = {intent, gesture, a_bin, v_bin, style}
3

采样噪声和时间

采样高斯噪声 z 和连续流时间 t，构造中间状态 x_t。

x_t = (1 - t) · z + t · x_data

推理时从语言生成安全动作候选

推理过程保守处理：先生成多个候选，再做安全排序，最后只执行短窗口。 这比一次性生成长动作更稳，也便于接入实时机器人状态。

短窗口执行 执行前 0.5 秒，再重规划
推荐推理策略 先预测可解释的中间 code，再生成短轨迹窗口，但只播放前若干帧；每次重规划都把机器人真实 q0/dq0 塞回模型。 这样动作可以持续，又不会因为长序列生成误差导致姿态漂移。
安全边界 低置信度 code、超限候选、碰撞候选、穿模候选全部降级为 null gesture + neutral style 或保持当前姿态。 模型输出不是最终控制命令，必须被安全层接管。

Implementation Plan

最小可训练闭环

先做能 overfit、能采样、能预览的小模型。不要一开始做巨大网络，先证明语言条件和动作分布是可学的。

1. Dataset JSONL + CSV window loader，按 fps 读取源窗口，轨迹归一化，质量过滤，派生 codebook 监督。
2. Model Frozen text encoder + code adapter + condition fusion + 8 层 Transformer flow expert。
3. Train 先用 partial overfit，再全量训练；记录 flow/code loss、preview 和 checkpoint。
4. Sample prompt 先生成可解释 code，再生成候选轨迹，guidance 控制文本/code 强度。
5. Validate MuJoCo 安全过滤，导出并排预览，人工筛选高质量样本。
